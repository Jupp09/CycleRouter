# CLAUDE.md

CycloRouter (repo name: CycleRouter) is a bike route planner for road bikes, gravel bikes and trekking bikes, built on OpenStreetMap. It is a static vanilla-JS single-page app with an optional small Node server. The user-facing README is in German ([README.md](README.md)).

## Commands

```sh
npm install          # only runtime dependency: mariadb (needed only when using accounts); dev: typescript, @types/node
npm run check        # typecheck + unit tests, no browser, no network, a few seconds (also runs in CI on every push)
npm run check:live   # check a deployed instance from outside (default https://cyclorouter.de; pass a URL to change)
npm start            # node server.mjs → http://localhost:8000 (PORT=… to change)
npm run warm -- <lat> <lon> [radius-km]   # preload the POI cache for a region, e.g. 53.07 8.80 60
npm run extract:update   # download the current Europe extract now (the server also does this by itself)
npm run extract:build    # build the extract locally (Linux/macOS with curl + osmium-tool, ~30 GB download)
```

- **No build step, no bundler, no linter.** To check a change, run `npm run check`, then `npm start` and use the app in a browser, then `npm test`. The browser console and the server log are the diagnostics; uncaught browser errors of real users also land in the server log as `Browserfehler: …` ([js/errorReport.js](js/errorReport.js) → `/api/client-error`, [server/clientErrors.mjs](server/clientErrors.mjs)).
- **Type checking without a build** (`npm run typecheck`, [jsconfig.json](jsconfig.json), TypeScript 7 as a checker only, `strict` off): it checks JSDoc types in `js/`, `server/`, `scripts/` and `tests/unit/`, and must stay at 0 errors (CI fails otherwise). The route object is typed in [types/route.d.ts](types/route.d.ts) (`Route`, `Waypoint`, `Segment`, `Coord`, global, no import needed); arrays with extra properties (`PoiList`, `PlaceResults`, `RouteList`), `LogFn`, the Leaflet global and `navigator.standalone` are in [types/globals.d.ts](types/globals.d.ts). A new property on the route object goes into `Route`. Destructured options need a JSDoc `@param` (TypeScript drops destructured names without a default from the inferred type, and then only matches the tag if all parameters before it are documented too). `sw.js` is not checked (it would need the webworker lib, which conflicts with dom). `types/` is never served.
- **Unit tests** (`npm run test:unit`, `node --test`, [tests/unit/](tests/unit/)): pure functions of the domain modules and the server (opening hours, climbs, tiles, limits, `limitKey`, BRouter parameters, `cleanRoute`, CSP hashes, module graph). No browser, no network, no DB; time zone matters for opening hours, CI sets `TZ=Europe/Berlin`. Modules that touch browser globals at load time (everything in `js/app/`, `errorReport.js`, `poiTiles.js`'s IndexedDB at call time is fine) can't be imported there, so keep testable logic in the domain modules. `tests/run.mjs` only picks up `tests/*.test.mjs`, so the two suites don't mix.
- **Browser tests** (`npm test`, [tests/run.mjs](tests/run.mjs)): start their own server on port 8765 (`DB_HOST=''`, `POI_EXTRACT_URL=off`) and Edge/Chrome headless (`CHROME_PATH` to override), then run `tests/*.test.mjs` one after another. `npm test -- keyboard a11y` runs only those; `TEST_URL=https://cyclorouter.de/ npm test -- route` runs them against a deployed instance instead of a test server (accounts still come from the fake; that instance has its own BRouter, which `brouter`, `settings` and `edge` detect via `/api/brouter`; run single suites there, since many full runs in a row from one address may get it blocked by the host); `--shots` saves screenshots to `tests/out/`, `--headed` shows the window. Every run also writes `tests/out/bericht.html` ([tests/lib/report.mjs](tests/lib/report.mjs): overview, a duration bar per test, steps with their checks, screenshots, and the history of the last runs from `tests/out/verlauf.json`, which makes flaky tests visible). Running the whole suite many times in a row gets this address throttled by brouter.de (403 "Please, retry later!"); the app then falls back to Valhalla, and tests that compare lengths or stage splits fail – check with a direct request before hunting a bug. No dependencies: the DevTools protocol over Node's built-in `WebSocket` ([tests/lib/browser.mjs](tests/lib/browser.mjs)), every page in its own browser context. `page.setOffline(true)` cuts the network for the page *and* its service worker (and makes the account fake fail requests). Accounts come from an in-memory fake of the account API that intercepts the browser's requests ([tests/lib/fakeAccount.mjs](tests/lib/fakeAccount.mjs)), so the server's SQL is *not* covered; keep the fake's responses in line with `accountApi.mjs`. The tests call the live services (BRouter, Photon, Nominatim, tiles), take a few minutes and can fail when brouter.de is busy. A test is a module with `export default async function (t)` using `t.page()`, `t.check()`, `t.step()`; shared expressions are in [tests/lib/app.mjs](tests/lib/app.mjs). Any JS error or system dialog (`alert`/`confirm`) on a page fails the test.
- The app must be served over HTTP, because ES modules don't load from `file://`. Any static server started in the project root also works (`py -m http.server 8000`), but you lose the POI cache, home-region preloading and accounts. The client detects a missing server and falls back to calling Overpass directly.
- Node ≥ 20.12 is needed for `process.loadEnvFile` (`.env`). On older Node versions, or on hosts like Phusion Passenger that start `server.mjs` directly, the variables must come from the environment.
- Accounts need MariaDB ≥ 10.5 or MySQL ≥ 8.0.16 and `DB_*` variables in `.env` (see [.env.example](.env.example)). Without `DB_HOST` the server runs normally and the client hides all account features.

## Conventions

- **German everywhere:** UI text, error messages shown to users, code comments, JSDoc and log output. Numbers and dates use `de-DE` formatting through the helpers in utils.js (`formatKm`, `formatM`, `formatNumber(n, options)`, `formatClock`, `formatDate` …), not `toLocaleString` directly: they keep one `Intl` formatter per option set, which is 14–40× faster (stop planning formats thousands of values), and they are created on first use so they pick up the page's time zone. New code should follow this. Identifiers are in English.
- Plain ES modules (`"type": "module"`), modern syntax (`??=`, `Object.hasOwn`, `AbortSignal.any`), no framework. The DOM is accessed with `$ = document.querySelector` (and `$$` for all matches as an array; both typed `any` on purpose, see dom.js) and built by hand with `replaceChildren` and the helpers in dom.js (`el(tag, className, text)`, `span`, `popupBox`, the button helpers), which set text via `textContent`. `innerHTML` is used only for static markup skeletons, never for OSM, user or server data (POI names, labels).
- Leaflet 1.9.4 is a **global** (`window.L`) loaded from cdnjs in [index.html](index.html); it is not imported.
- Every network call takes an `AbortSignal`. `run()` in [js/app/pipeline.js](js/app/pipeline.js) aborts the previous calculation when a new one starts. `AbortError` is always swallowed silently, so keep that pattern when adding async work.
- Persist settings in the browser only through `storage.get/set` in [js/utils.js](js/utils.js). It adds the `cyclerouter.` prefix, handles JSON and private mode, and notifies `onStorageSet` listeners, which drive account settings sync.
- Comments explain the *why*: rate limits, data quirks, privacy decisions. Keep them up to date when you change behaviour.
- **Accessibility** (checked with axe-core and a keyboard test; 0 axe violations in light and dark):
  - Anything clickable is a `<button>` or a link, never a clickable `<li>`/`<div>`. List rows use `rowButton()` from `js/app/dom.js`, and its content must be phrasing elements (`span()`), not `<div>`.
  - Switches are `role="radiogroup"` with `role="radio"` + `aria-checked` buttons. `dom.js` adds arrow keys and the single tab stop automatically for every radiogroup in the page.
  - Things users only see happen are spoken via `announce()` ([js/announce.js](js/announce.js)). `setStatus()` already does this; `run()` announces the finished route. Don't add announcements for automatic refreshes.
  - The map (`#map`) is a `role="group"` named „Karte“ with the keyboard hint `#map-help` (index.html). Leaflet's own English texts are replaced in `createMap` (zoom buttons, layers toggle, attribution prefix, popup close button „Schließen“); a new Leaflet control needs German titles too.
  - Popups: opened from a keyboard-focused element (`:focus-visible`: list row, Enter on a marker), focus moves into the popup content; Escape closes it and focus returns to the opener (`map.js`, tested in popups.test.mjs). With mouse or touch, focus stays where it was.
  - Target size ≥ 24 px (WCAG 2.5.8): small map markers use the `marker-hit` icon class, a larger invisible hit area around the visible pin (start/end/manual stops/water 32 px, via 24 px); `summary` and `.link-btn` have `min-height: 1.5rem`.
  - Messages in a dialog are announced as well: `renderAccount(message)` calls `announce()` (errors urgent); redraws without a message stay silent.
  - Map markers get a name (`title`, which `map.js` also sets as `aria-label`). Inputs get a real `<label for>` or `aria-label`, not just a placeholder. The place search follows the combobox pattern (`geocode.js`).
  - Colours: text links and focus outlines use `--accent-text`, white-on-accent buttons use `--accent`. Body text needs ≥ 4.5:1, focus outlines and other UI parts ≥ 3:1, in both schemes.
  - Colour never carries information alone. The `CATEGORIES` palette in `surfaces.js` is Okabe-Ito based and checked for protanopia/deuteranopia; unpaved categories have `dash`, which the map line (`dashArray`) and the legend swatch both show. The grade classes get darker with steepness and additionally carry `pattern` (hatching in the elevation profile, denser when steeper) and `dash` for the two steepest. Check a new category against the existing colours under colour-blindness simulation. Start and end markers (map and the dots in the form) differ in lightness and shape, not hue: start a light ring, end dark with a flag (`FLAG` in map.js). Supply stops and water whose opening state warns (`WARN_STATES`) get a dashed border and a „?“ badge, and the state is appended to the marker's name (`warnNote` in supplyView.js). While a route is shown, a collapsible legend (`createLegend` in map.js, Leaflet control top left, open state in storage `legendOpen`) explains the markers; its icons share the pin CSS but use their own classes (`.pin-stop` etc.), so selectors like `.stop-pin` in code and tests never count the legend. Supply stops, water and search results share one layer (`poiLayer`); below zoom 13 (`CLUSTER_UNTIL`) `refreshPois` merges markers closer than 34 px into one dark count marker (`.cluster-pin`, grouping in [js/cluster.js](js/cluster.js), unit-tested). It carries the counts per kind in `data-stop`/`data-water`/`data-search`, so tests count markers with `markerCount(kind)` from tests/lib/app.mjs, never with `.water-pin` alone; a click or Enter zooms to its places. A marker with an open popup always stays single, and `openStop`/`openWater`/`openSearchResult` call `reveal()` before opening the popup. `named()` sets the aria-label on every `add`, because Leaflet rebuilds the element when a marker returns to the map.
  - Font sizes are in `rem` (the browser's base font size counts), never below `0.75rem` (12 px). Exceptions: emoji inside map markers, whose Leaflet icons have a fixed pixel size.
  - The elevation profile redraws at most once per animation frame and only when what it draws changed (coords, segments, breakdown, size, font size; `drawIfChanged` in elevation.js), because the pipeline shows a new route object after every step. The elevation profile is a `role="slider"` (arrow keys, Page ↑/↓, Home/End) with a text summary (`elevationSummary`) as description; the SVG itself is `aria-hidden`.
  - `prefers-reduced-motion`: map jumps pass `motion()` (`map.js`), so add it to any new `setView`/`fitBounds`/`flyTo`. `forced-colors`: the selected switch button gets `Highlight`; the blocks for both media queries are at the **end** of `style.css` so they override the normal rules (the `@media print` block for the roadbook sits just before them).
  - `flashStatus()` messages stay until the user's next click or key press (at least 4 s), not for a fixed time.

## Architecture

### Frontend (`js/`, loaded by `index.html` → `js/main.js`)

`js/main.js` is only the entry point: it imports the UI modules in [js/app/](js/app/) and starts them (`syncUi()`, `initHome()`, `initAccount()`). The modules outside `app/` hold the domain logic and don't touch app state.

Views don't call each other to refresh. `showRoute()`/`clearRoute()` emit `'route'` (route or `null`), and each view renders its own part. Other events: `'start'` (start point changed, e.g. holiday hint for the departure), `'stages'` (multi-day state changed while no new route is shown) and `'account'` (signed in/out, account deleted, session expired: accountView redraws the account box, routesView the save buttons and "Meine Routen"; emit it *before* `renderAccount(message)`, because its handler redraws the box without a message). Direct imports between views exist only for actions (e.g. `alongView` → `addVia`).

**Import cycles are intended** (e.g. `pipeline` ↔ `waypoints`, `controls` → `pipeline` → …). They are safe because cross-module exports are **function declarations** (hoisted), and modules only attach DOM listeners and `on()` handlers while loading. Calls to other `app/` modules happen inside handlers, never at module top level. The only exceptions are `state.js`, `dom.js` and `mapView.js`, which are not part of any cycle and can be used at top level. Keep it that way when adding a module, and don't export `const` arrow functions that other modules in a cycle call.

**Route object** (shared by all providers): `{coords: [[lat, lon, ele]], cum: [m], distance, ascent, descent, waypoints, segments}`. Waypoints are `{lat, lon, label?, manual?, icon?, stop?, stay?}`.

**Calculation pipeline** (`run()` in [js/app/pipeline.js](js/app/pipeline.js)): base route → optional multi-day step (`withStays`: plan stays, re-route through them) → optional supply step (`withSupply` / `addStops`: re-route through stops) → holiday step. The holiday check (`holidayContext`: regions via Nominatim at 1 request/s, then date.nager.at) starts in parallel with the supply step but is not awaited by it. Stops are planned without holidays first (`holidayCheck: 'pending'`). `applyHolidays` then only attaches the regions, unless a holiday actually falls on a riding day, in which case the stops are planned again. Region borders are only located precisely (`regionsAlong(…, {precise})`) when a holiday applies. Each step returns a *new* route that keeps the previous one:

- `route.origin`: the route without stays or stops
- `route.base`: the route before stops were added
- `originRoute()` = `origin || base || route` is the starting point for any re-plan (`replanStops()`)

The route is shown after each step, so it is usable before the stop search finishes.

**Loop detection depends on object identity:** `isLoop(r)` checks `waypoints[0] === waypoints[last]`. `restoreRoute` (routesView.js) rebuilds that identity on purpose, and any code that copies waypoints must keep it.

**Imported tracks (GPX) must survive re-routing.** Stops, stays and vias are added by re-routing through waypoints, which would replace an imported track with the provider's own route. So `trackRoute()` (routing/index.js) marks the route `track: true` and gives start and end a `trackAt: {coords, segments, i}`; `shapeAnchors()` (routeGeometry.js) adds an invisible anchor waypoint (`anchor: true`, with `trackAt`) about every km. In `route()`, a leg between two points with `trackAt` on the same `coords` is a slice of the track with no request; only the legs next to an inserted stop, stay or via are routed (also per leg with ORS). Anchors get no marker (mapView) and are not saved; a saved route gets `data.track: true` and `restoreRoute` rebuilds it with `trackRoute`. `state.track` holds the imported route, and `activeTrack()` returns it while mode is `ab` and start/end are still its objects; `calcAB()` then routes along it (`alongTrack`). Moving start or end ends that: the next full recalculation is an ordinary route. Track slices without routing data have surface `unknown` / way type `other`. `locateOnRoute` would find the end of a round trip at its start, so code that places anchors uses `trackAt.i` instead.

**Saved routes** contain only the origin route (coords, segments, manual waypoints) and `stayChoices` (OSM ids). Stops and stays are planned again when the route is opened.

### Routing providers

A provider is `{id, name, supportsTraffic, supportsEurovelo?, perLeg?, route(points, opts, signal), roundTrip?(...)}` and returns `{coords, segments}`.

`route()` in [routing/index.js](js/routing/index.js) is the only entry point; don't call `provider.route` directly (except `roundTrip`). For providers with `perLeg` (BRouter, Valhalla) it requests each pair of consecutive waypoints separately, at most 2 at a time, and keeps each leg for 1 h (LRU, 400 legs). Adding a stop or stay, a re-plan or toggling an option back therefore only requests the changed legs. Identical legs requested at the same time share one request (`shared()`), which is aborted only when every waiter has aborted. Cached legs are shared between routes, so never mutate a route's `coords`. ORS is not split, because each request counts against the user's daily quota.

**Busy handling:** BRouter retries after 2 s and 5 s when brouter.de answers "retry later"/timeouts/5xx or drops the connection. The status line shows this via `onRoutingNotice` (set in pipeline.js). If it still fails, the error has `busy: true` and `route()` computes that leg with **Valhalla** (FOSSGIS server, [routing/valhalla.js](js/routing/valhalla.js)); for the next 60 s further legs skip the retries. Fallback legs are cached for only 5 min. The route then has `fallback: 'Valhalla'`, and resultsView shows a hint. Errors that are not about load (point not routable) never fall back. Valhalla is not selectable in the settings: it rates ways differently and has no EuroVelo preference, and its usage policy allows only moderate use. Its surface/way type come from a second `trace_attributes` call, mapped onto the coordinates by edge length.

- **Own BRouter server** (optional): with `BROUTER_URL` in `.env`, [server/brouterProxy.mjs](server/brouterProxy.mjs) forwards `GET /api/brouter?…` and `POST /api/brouter/profile` to it (only known parameters; per-IP budget; a queue of `BROUTER_PARALLEL` requests, because BRouter kills requests beyond its thread count after 2 s). It goes through the Node server because such a server usually speaks only `http://`, which the https page may not call (mixed content). The client asks `GET /api/brouter` once per session (`{enabled}`, 404 without `BROUTER_URL` or without server) and then tries the own server first, without retries; on failure (unreachable, busy, missing data files or profile) that leg goes to brouter.de with the usual retries and Valhalla fallback. After a busy/unreachable answer the own server is skipped for 60 s. Each BRouter leg carries `server` (`'own'` or `'brouter.de'`); `route()` sums the metres per server into `route.servers`, and resultsView shows the line `#routing-server` (with shares when both were used). "Point not routable" errors don't fall back. Uploaded profile ids are per server, so the upload cache is keyed by endpoint. Requests to the own server also get `OWN_SEARCH` (brouter.js: `pass1coefficient=1.2`, `pass2coefficient=-1`, i.e. one directed search instead of BRouter's two passes; about twice as fast, route cost +0–0.2 %); brouter.de keeps the default search. The proxy must pass `profile:` keys unencoded, because BRouter ≥ 1.7.11 decodes only values, and an encoded key is silently ignored. `tests/run.mjs` sets `BROUTER_URL` from `TEST_BROUTER_URL` (default empty, since several tests look for brouter.de requests); [tests/brouter.test.mjs](tests/brouter.test.mjs) covers both cases.
- **BRouter** (default, no key): profiles per bike/traffic in `PROFILES`. For the EuroVelo preference, the client loads the `.brf` from [profiles/](profiles/), rewrites `costfactor` in `patchProfile()`, uploads it to brouter.de (20 s timeout; the upload is shared by all waiting legs, and each waiter gives up on its own abort) and caches the profile id for 6 h. If BRouter later rejects the id, the client uploads it again. The `.brf` files live in this repo because brouter.de doesn't serve them with CORS headers. Don't reformat them, since `patchProfile` matches `^assign costfactor`.
- **OpenRouteService**: needs an API key that the user enters in settings. The key is stored in `localStorage` only and **never synced to the server**. ORS also has a native `roundTrip`.

### POI data, layers and caching

The POI layers in `LAYERS` ([poiSource.js](js/poiSource.js)) are `supply`, `food`, `stay` and `service` (railway stations, bike shops, repair stations, compressed air, e-bike charging: one layer on purpose, because every layer costs its own request and warm-up per tile). Each POI type belongs to exactly one layer (`layerOfType`). Each layer is fetched and cached per tile on its own. When looking up a tile, the client tries these sources in order:

1. Memory and IndexedDB (`cyclerouter` db, `poiTiles` store, 7 days; the db is opened by [offlineStore.js](js/offlineStore.js)): [poiTiles.js](js/poiTiles.js)
2. The server, `POST /api/pois`: a file cache at `cache/pois/<layer>/<tile>.json` with 30-day TTL (`POI_TTL_DAYS`), stale-while-revalidate, and up to 365 days stale ([server/poiCache.mjs](server/poiCache.mjs)). The server also has the **Europe extract** (see below); per tile the newer of the two wins.
3. Overpass directly, in chunks of 40 tiles

**Europe extract:** a GitHub Actions workflow ([.github/workflows/poi-extract.yml](.github/workflows/poi-extract.yml), weekly) runs [scripts/build-poi-extract.mjs](scripts/build-poi-extract.mjs). It processes the Geofabrik extracts of all European countries one by one (composite regions like `dach`/`alps` are skipped): `osmium tags-filter` with each layer's `filters`, then `osmium export` to GeoJSON lines, then `toPoi` (the same conversion as the Overpass path). The result goes to the release `poi-data`: `pois-europe.ndjson.gz` (one line per 0.5° cell = 5 × 5 tiles) and `pois-europe.json` (manifest with sha256). [server/extract.mjs](server/extract.mjs) checks the manifest 1 min after start and then every 12 h (`POI_EXTRACT_URL`, `off` disables it). It stores the cells in `cache/extract/cells/` and swaps them in only after the checksum matches. `npm run extract:update` updates by hand. Only cells that lie fully inside the processed countries are in the bundle; a missing tile inside a covered cell means "no POIs". So an empty layer would hide existing data. The build therefore fails if a layer has no POIs, and the server counts POIs per layer (`meta.counts`) and uses only layers with data. `osmium export` gives `@timestamp` in seconds, Overpass gives ISO text, and `toPoi` handles both. Geofabrik refuses some GitHub runner machines (ECONNREFUSED, or 404 for everything): after 3 countries in a row fail, the script writes `dist/retry` and stops, and the workflow dispatches itself again (`attempt` input, at most 3 runs), since a new run usually gets another machine; the last attempt takes the remaining countries from download.openstreetmap.fr (about half of them exist there under the same name) and uses that mirror's `.poly` ([scripts/poly.mjs](scripts/poly.mjs)) for coverage, because its borders differ. Lines are read with `lines()` ([server/lines.mjs](server/lines.mjs)), never `node:readline`, which also splits at U+2028/U+2029 inside OSM names. Everything else (and layers the bundle doesn't know, e.g. after a `cacheVersion` bump) still goes to Overpass.

**Keep `statements` (Overpass) and `filters` (osmium) of a layer in sync.** A change to `js/poiSource.js` triggers a rebuild of the extract.

With `cacheOnly` the caller gets only what is cached. Missing tiles are loaded in the background, by the server or, without a server, by the browser itself. Supply stops wait for the `supply` layer but take `food` (bakeries, cafés) as `cacheOnly` (`route.foodPartial`), because a cold Overpass request often takes 30+ s. "Find along the route" works the same way.

To add a layer: add it to `LAYERS` (with `statements` and `filters`), add its types to `LAYER_OF_TYPE`, add any tags you need to `KEEP_TAGS`, then **restart the server**. An old server rejects an unknown layer, and the client then fetches from Overpass and logs a warning.

Several layers of the same tiles go into **one** Overpass query (`fetchLayersFromOverpass`), because every query waits in Overpass's queue on its own. The server groups tiles by their combination of missing layers.

Be gentle with the public services. The server sends at most 2 parallel Overpass requests and a descriptive `User-Agent` (Overpass returns 406 without one). Requests a user waits for (`urgent`) go ahead of background work in that queue. The warm queue ([server/warmQueue.mjs](server/warmQueue.mjs)) has two job kinds: home regions (200 km radius) and routes. After every calculated route the client sends the route's tiles to `/api/warm-route` (`warmRoute()` in poiTiles.js, once per tile per session). Route jobs run before region jobs, and a region is interrupted between chunks for them. The queue yields to urgent requests (`isBusy()`), pauses between chunks and is rate-limited per IP and job kind.

### Server (`server.mjs`, `server/`)

- Plain `node:http`, no framework. **`import './server/env.mjs'` must stay the first import.**
- Static files are served only from a **whitelist** (`PUBLIC` regex in [server.mjs](server.mjs)): `index.html`, `manifest.webmanifest`, `sw.js` (must sit in the root: a service worker only covers paths below its own folder), `js/`, `css/`, `profiles/`, `assets/`. A new public top-level file or folder must be added there, or the server returns 404. Don't use a top-level `/icons/` path: Apache (Plesk at cyclorouter.de) aliases it to its own icons, so such requests never reach Node. The whitelist keeps `.env`, `server/` and `cache/` private.
- [.htaccess](.htaccess) mirrors that whitelist for Apache. It protects `.env` and the server code if the project folder is ever served as plain files without Node. That happened after the move to cyclorouter.de, and `/.env` was reachable. Keep it in sync with `PUBLIC`. It also allows `/api/`.
- [server/static.mjs](server/static.mjs) serves those files from an in-memory cache (checked by mtime/size) with `Cache-Control: no-cache` + `ETag`, so a returning browser gets `304`s and an update still applies at once. It ignores the `-br`/`-gzip` suffix Apache adds to ETags. For `index.html` it injects `<link rel="modulepreload">` for every module statically imported from `js/main.js` (found by parsing `import … from '…'`; the list is rebuilt at most every 2 s). Keep the `<script type="module" src="js/main.js">` tag exactly as it is, since the injection looks for it. Dynamic `import()` is not followed.
- **Timing:** `run()` in pipeline.js logs one `console.info` line per finished calculation (`Berechnung: Grundroute … · Orte laden … · … · gesamt …`). Check it before optimising.
- Endpoints: `/api/brouter` (see Routing providers), `/api/pois`, `/api/warm` (home-region preloading; the client sends coordinates rounded to ~10 km, the server snaps them to the tile centre), `/api/warm-route` (tiles along a route, the same 0.1° tiles `/api/pois` gets), `/api/regions` ([server/regions.mjs](server/regions.mjs): country/state per 0.01° grid key, shared file cache `cache/regions.json`, one Nominatim queue for all users at ≤ 1 request/s, per-IP budget `nominatimBudget`; answers within 5 s and lists the rest as `missing`, which the browser then asks Nominatim for itself), `/api/client-error` ([server/clientErrors.mjs](server/clientErrors.mjs): uncaught browser errors into the log only, nothing stored; per-IP and global limits, the same error once per hour), and the account API in [server/accountApi.mjs](server/accountApi.mjs) (route table in its header comment).
- [server/db.mjs](server/db.mjs): tables are created at startup with `CREATE TABLE IF NOT EXISTS` from `SCHEMA`. **There are no migrations.** New tables work automatically, but a new column on an existing table needs explicit `ALTER` handling. Always use parameterized `query(sql, params)`.
- [server/auth.mjs](server/auth.mjs): scrypt password hashes (N=2^14, r=8, p=5: OWASP-equivalent to N=2^17 at 16 MB instead of 128 MB; the parameters are stored in each hash, and `needsRehash` upgrades older ones on the next successful login; `passwordProblem` rejects common passwords for new passwords only), a session token in the HttpOnly `cr_session` cookie (stored only as a SHA-256 hash), limits on failed logins (per IP and per username) and registrations (per IP and 50 per day server-wide, because every account may store 50 MB), at most 2 scrypt runs at a time (20 waiting, then 503; scrypt shares Node's thread pool with all file access), and `Secure` when `PUBLIC_URL` is https or proxy headers say so.
- **`clientIp()`** is the basis of every limit. It trusts `X-Forwarded-For` only if the connection comes from a loopback/private address (a local proxy) and then takes the rightmost non-internal entry. It returns a limit key, not the raw address: IPv6 is cut to its /64 network (`limitKey`), because one connection usually owns a whole /64 and could otherwise take a fresh address per request; `::ffff:a.b.c.d` becomes plain IPv4. `TRUST_PROXY=off` ignores the headers; `DEBUG_IP=1` logs the first 20 decisions.
- [server/rateLimit.mjs](server/rateLimit.mjs): `createLimiter({windowMs, max})` with weighted sliding windows. It prunes expired entries per key; never clear the whole table (that would let an attacker with many IPs reset a running lockout).
- `/api/pois` has an Overpass budget per IP (`overpassBudget` in server.mjs, tiles × layers per hour). Only tiles the server must fetch from Overpass count. When it is used up the server answers 429 and the client loads from Overpass itself (`poiTiles.js`).
- [server/security.mjs](server/security.mjs): security headers on every response and the CSP for `index.html`. **A new external service the browser calls (API, tile server) must be added to `CONNECT` or `IMAGES` there**, or the browser blocks it. Inline scripts are allowed by hash, computed from the file at serve time (CRLF normalised). Leaflet is loaded with SRI `integrity` in index.html; a Leaflet version change needs new hashes (cdnjs lists them).
- Saved routes: at most 500 per account and 50 MB in total (`checkQuota` in accountApi.mjs).
- [server/http.mjs](server/http.mjs): shared helpers `HttpError`, `sendJson`, `readBody` (with size limit).
- Account API rules: mutating requests must be `application/json` and same-origin (`checkOrigin`, CSRF protection). Throw `HttpError(status, germanMessage)` for client errors. Error responses for server-side failures carry a generic message; details go to the log only.
- The GitHub Actions in the workflow are pinned to commit SHAs (comment shows the version). Update both when upgrading.

## Things to keep in sync

- [js/shared.js](js/shared.js) holds the values that the browser and the server share: `SYNC_KEYS` (synced settings; the server drops any other key), `MODES` (`ab | distance | loop`) and `BIKES` (`road | gravel | trekking | ebike`). Like `poiSource.js`, it is loaded by Node, so it must not use browser APIs. Add a new synced setting there and nowhere else. It also holds `scrub()`, which removes locations (URL query/fragment, coordinates) and control characters from error reports; browser and server both use it.
- Client code also uses the `mode`/`bike` values as keys in `PROFILES` (brouter.js, ors.js), `BICYCLE_TYPE` (valhalla.js), `DEFAULT_SPEED`/`CLIMB_RATE` (utils.js), `BIKE_LABELS`/`MODE_LABELS` (state.js) and the switch buttons and "Auswahl anpassen" checkboxes in index.html. A new mode or bike type needs entries in all of those as well as in `MODES`/`BIKES`.
- **E-Bike** routes with BRouter's `trekking` profile plus `PARAMS.ebike` (brouter.js): profile parameters go into the URL as `profile:<name>=<value>`, which also works for uploaded EuroVelo profiles. Booleans must be `0`/`1`; brouter.de doesn't answer `false`.
- `visibleBikes`/`visibleModes` (state.js, synced) choose which buttons the switches show. `showOnly()` in controls.js keeps the active value visible and hides a switch with fewer than two buttons; the radiogroup keyboard handling in dom.js skips hidden buttons.
- [README.md](README.md) (German) documents features, setup and the module overview. Update it when behaviour that users see changes.

## Notes

- `cache/`, `node_modules/`, `dist/`, `tmp-extract/` and `.env` are git-ignored. `.env` holds real DB credentials, so never commit it or print its contents.
- Development is on Windows; git warns about LF→CRLF line endings, which is harmless.
- The app is installable as a PWA (`manifest.webmanifest`, iOS meta tags in `index.html`) and starts offline through a small service worker ([sw.js](sw.js), registered in `js/main.js`). App files are **network-first** (cached copy only when the network fails or takes over 3 s), so an update still applies at once; Leaflet from cdnjs is cache-first; `/api/`, map tiles and all other services are never touched. Keep it small: a broken service worker stays with users until the browser fetches a new one. On a first visit the page loaded its files before the worker took control, so `main.js` sends it the list of loaded files once (`precache` message). The map stays grey offline (no tile caching, by decision).
